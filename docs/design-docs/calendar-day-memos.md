# Design Doc: カレンダーで日ごとのメモを見る

プラン: [docs/plans/calendar-day-memos.md](../plans/calendar-day-memos.md)（作業の詳細と、確認の手順はそちら）｜issue: #68

## 1. 背景と範囲

- カレンダー（`/calendar`）は、予定のある日を見せるだけで、その日に何を書いたかは見られない
- カレンダーは、あとから日ごとのメモと日報を見られる画面に育てる前提で作った（`docs/design-docs/schedule-calendar.md`）
- 範囲: カレンダーで日を選んだときの右の枠に、「この日のメモ」の節を足す。Web だけの変更

## 2. 目標と非目標

目標:
- 日を選ぶと、その日（JST）に書いたメモを、書いた時刻の順に見られる

非目標:
- グループに入ったメモを出すこと
- 月表示のマスに、メモを書いた日の印や件数を出すこと
- カレンダーからメモを編集・削除すること
- 日報、日付で絞る専用の API

## 3. 設計

### 全体像

- 今のカレンダーは、メモ一覧の取得（`GET /api/memos`）から予定を選び、予定日でまとめている。同じ取得結果から、予定以外のメモを作成日でまとめ直す
- 右の枠（`DaySchedulePanel`）の「予定」の節の下に、「この日のメモ」の節を置く。スマホではカレンダーの下に縦に並ぶ
- 1件は、書いた時刻（JST）・タグのバッジ・本文（3行で切る。画像はサムネイル）。見るだけで、操作は置かない

### API と契約（`packages/shared`）

なし（変えない）

### データ

なし

### 処理の流れ

1. `CalendarView` が `["memos"]` の取得結果を受け取る
2. 純粋関数 `groupMemosByCreatedDate` が、予定を除き、`createdAt` を JST に直した日付でまとめ、各日を古い順に並べる
3. 選んだ日の分を、`DaySchedulePanel` のメモの節に渡す

### 制約

- 日付と時刻は JST で決める（予定の機能と同じ。端末のタイムゾーンに依らない）
- 色とバッジは `config/tag-meta.ts` の既存のものを使う（`.agents/rules/design.md`）
- `GET /api/memos` はグループに入ったメモを返さないので、グループに移したメモはカレンダーから消える

## 4. 検討した代替案

| 論点 | 採った案 | 採らなかった案と、理由 |
| --- | --- | --- |
| メモを分ける日付 | 作成日（JST） | 予定も含めてすべて作成日で分ける案。予定の節が予定日で出ているので、軸が混ざる |
| 予定を「この日のメモ」にも出すか | 出さない（予定は予定日にだけ） | 作成日の節にも出す案。同じ予定が2か所に出て、どちらの日の話か分かりにくい |
| グループのメモ | 出さない（今の取得をそのまま使う） | 日付で絞る取得 API を新しく作り、グループのメモも出す案。API と契約の変更が要り、今回の目的（その日に書いたことの振り返り）には過剰 |
| 表示の形 | 予定と同じ枠に節を足す。見るだけ | メモタブのカードをそのまま並べる案（狭い列で縦に長い）。「予定」と「メモ」をタブで切り替える案（1日をひと目で見られない） |
| マスの印 | 付けない（点は予定だけ） | 別の色の印か、件数を出す案。点の意味が変わり、マスが混む |
| 時刻の表示 | JST | メモタブと同じく端末の時刻で出す案。日付を JST で切るので、時刻だけ端末時刻だと日付と時刻がずれうる |

## 5. 横断的な考慮事項

セキュリティ（認可）:
- 変更なし。メモは既存の `GET /api/memos`（セッション必須、自分のメモだけ）、画像は既存の `/api/memos/:id/image`（セッション必須、持ち主の確認あり）で出す

プライバシー（ログ）:
- なし（ログを足さない）

運用:
- 失敗・読み込み中・オフラインの表示は、今のカレンダーのもの（予定と共通の1つの取得）をそのまま使う
- 1日のメモの件数に上限は設けない。重くなったら、日付で絞る API を検討する
