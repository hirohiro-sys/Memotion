# create-pr（PR本文を構造化して投稿する）

承認前に `gh pr create` しない。

## 1. 差分と経緯を集める

- `git diff main...HEAD` で変更の全体を把握する
- 対応するプラン（`docs/plans/`）と、実装後の AI レビュー結果を読む。プランやレビュー結果が無いときは、あるように書かず、本文に未添付と書く

## 2. 本文を下書きする

次の見出しで、レビューアーが上から読めば理解できる順に書く。

- 課題: 何を解決する PR か（背景と、対応する issue・プラン）
- 解決策: どう変えたか。設計判断とトレードオフを 1〜2 行で
- テスト: 追加・変更したテストと、手元での実行結果。実行していない項目は未実行と書く
- レビュー観点: とくに見てほしい箇所、影響範囲、未対応事項

下書きは `docs/pr/` に保存し、投稿前に人間の承認を取る。

## 3. 投稿する

承認後、未 push なら `git push -u origin HEAD` してから、`gh pr create` で本文を渡して作成する。CI と AI 相互レビューが回るので、その結果が出てから人間のレビューへ回す。
