# design-taste-frontend

色・余白・角丸の正本は `docs/design-system.md` と `apps/web/src/index.css`。手順の禁止事項は `.cursor/rules/design.mdc`。新しい色や余白は作らない。

## 0. 依頼文の読解（何よりも先に空気を読む）

コードに触る前に、ユーザーが本当に望むものを推定する。画面の種類は何か（製品UIか、LPか）、雰囲気を表す言葉はあるか、参照URLはあるか、読者は誰か。

書き始める前に、読み取った方向を1行で宣言する。方向は新しい流派を名乗るのではなく、既存の紙のノートのどの面を使うかで言う。

「メモ一覧を、Paper Warmth のキャンバスに、影のないカードと Notion Blue の主アクション1つで作る、と読んだ」

製品UI（ログイン、メモ、設定）では `text-display`、ヒーロー用の pill、キャラクターマークを使わない。LP でだけ `text-display` と `bg-marigold` を使ってよい。serif は編集者的な一文だけ。

## 0.D 決まりきった手癖の禁止

AI紫のグラデーション、暗い背景に中央寄せのヒーロー、3枚の均等なカード、何にでもガラス風の質感。これらはLLMの初期値である。読み取った方向に基づいて、意図的に避ける。

このリポジトリでは、それに加えて次も避ける。

- グラデーション、カードの `shadow-*`、ページ背景の `#ffffff`
- コンポーネントへの hex 直書き（`bg-[#0075de]` など）。`bg-primary` や `bg-marigold` を使う
- ダークで Midnight Ink をページ全面に敷くこと。`dark:` 用の色をコンポーネントに足すこと

実装後、ブラウザで変更した画面を操作して確認する。
